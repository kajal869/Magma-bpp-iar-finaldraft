# Magma Policy Draft Studio (internal demo)

Upload a closing slip and a quote (Excel). The portal reads them, shows which mandatory fields were captured / need checking / are missing, lets you fill the gaps (or leave them blank after a warning), and produces the policy **front pack** (schedule, premium summary, GST block, annexures) as a PDF.

- Frontend: React + TypeScript (Vite), Magma-themed, loading screen and light animations.
- Backend: FastAPI (Python). The PDF is rendered from a validated JSON model with Jinja2 + headless Chromium (Playwright).
- No database, no storage: uploads live in a temp folder for the length of one request; PDFs are held in memory for 15 minutes.

> **Extraction.** Both workbooks go through the `extractor/` package: closing-slip fields, quote headline (with policy-variant selection by the slip total), add-on rows matched to the clause library, per-section sum insured/premium, terms and annexures. Every value carries a status (captured / check / missing) and the review screen lets you edit fields, add-ons, sections and conditions before the PDF is built. The clause library, alias dictionary and customer cases are private (git-ignored); without them add-on matching is skipped with a warning. The repository ships one fictional case (ACME Precision Products, `app/cases/demo_laghu.json`) with matching sample inputs in `samples/`; it also supplies suggestions for policy-system fields. Real customer cases are never committed; see "Private cases" below.

## Quick start

**Mac:** follow [USER_GUIDE_MAC.md](USER_GUIDE_MAC.md) (step by step, with troubleshooting).

**Mac / Linux, short version**

```bash
git clone https://github.com/kajal869/Magma-bpp-iar-finaldraft.git
cd Magma-bpp-iar-finaldraft
chmod +x run_demo.sh && ./run_demo.sh      # opens http://localhost:8000
```

**Windows:** double-click `run_demo.bat` (or run it in a terminal). Needs Python 3.10+ and Node 18+.

Then upload `samples/demo_closing_slip.xlsx` and `samples/demo_quote.xlsx`.

## Manual run

```bash
python3 -m venv .venv && source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python -m playwright install chromium
(cd web && npm install && npm run build)
python -m uvicorn --app-dir server main:app --port 8000
```

Development with hot reload: keep the server running, then `cd web && npm run dev` and open http://localhost:5173 (it proxies `/api` to port 8000).

## Tests

```bash
pip install -r requirements-dev.txt
python -m pytest server/tests -q          # 9 tests, about 10 seconds
python app/tools/validate_cases.py        # schema + arithmetic check of every case JSON
```

The tests use only fictional data (generated by `samples/make_samples.py`).

## How it works

1. `POST /api/analyze` (closing slip + quote): runs the extractor and returns the mandatory-field list (status `ok` / `check` / `missing`, source, alternatives), the add-on rows (keep/drop, matched clause, review reasons), the 13 sections, the terms, and warnings.
2. `POST /api/render` (`sessionId`, `values`, `allowBlanks`, optional edited `addons`, `sections`, `terms`): applies the user's edits and renders the PDF. If required fields are empty, or a kept add-on has neither a clause nor "print as quoted", it answers `409` until the caller sets `allowBlanks`. `GET /api/clauses` lists the clause titles for the add-on dropdown.
3. `GET /api/pdf/{token}` (PDF, `?download=1` to attach), `GET /api/page/{token}/{n}` (page PNG for the preview), `DELETE /api/pdf/{token}`.

## Layout

```
server/            FastAPI app (main.py), field model (fields.py), tests
app/render.py      JSON -> HTML (Jinja2) -> PDF (Playwright)
app/templates/     front-pack template and stylesheet
app/schema/        JSON Schema of the case model
app/cases/         case JSON (only the fictional demo case is tracked)
web/               React + TypeScript app (src/App.tsx, src/components/*)
samples/           fictional demo inputs and the script that makes them
```

## Private cases (not committed)

To try a real case locally, put its case JSON (same schema as `demo_laghu.json`) in `app/cases/` and the matching closing slip and quote anywhere. `.gitignore` keeps everything in `app/cases/` except the demo case out of Git. Do not commit customer data, issued policies or customer workbooks; keep this repository private.

## Known limits

- Output is the front pack only (no wording book).
- PDF fonts: the layout is tuned for Calibri. Without it (default on a Mac) the stylesheet falls back to Carlito if installed; otherwise pages may reflow slightly.
- Signature images are not shipped; the demo case has `show_signature` off.
- Real quote extraction is pending (the team extractors are being integrated separately).
